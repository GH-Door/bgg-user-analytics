## Overview

보드게임 시장은 매출 규모로는 성장 중이지만 신규 유저 유입은 정체돼 있다. 업계는 원인을 "게임이 어려워서 초보자가 못 버틴다"와 "사놓고 안 하는 백로그 현상" 두 가지로 진단하지만, 실제 유저 행동 데이터로 검증된 적은 없다. 이 프로젝트는 BGG 유저 3,000명의 소유·평가·플레이 데이터를 직접 수집해 어디서 얼마나 다음 단계로 넘어가지 못하는지, 그 정체가 어떤 유저 특성과 함께 움직이는지, 시간이 지나도 그 구분이 유지되는지를 순서대로 검증한다.

**주요 성과:**
- 퍼널 최대 손실 구간을 **보유 → 첫 플레이(-32.5%p, 956명)** 으로 특정
- 보유 게임 수만으로 유저를 나누면 안 된다는 것을 규명하고, **보유 게임 수와 활용도 두 축을 교차**해 5개 유형으로 재정의(같은 변수로 군집화와 비교했을 때 일치도 **0.64**)
- 가설 3개 검정: H1 채택(효과 크기 **0.81**), H2 부분 채택, H3 채택(**85.5% → 47.0%**)
- **"위험군은 수집가형이 아니라 저관여형"** 이라는 통념 반전 발견(H2)
- 값이 없다는 뜻인데 `0`으로 채워져 있던 컬럼 5개를 찾아냄, 복잡도의 `0`(**31.6%**)을 걸러내자 복잡도-평점 상관이 **0.28 → 0.41**로 정정

## 🔬 Analysis

- **[01.EDA](jupyter/01.EDA.ipynb)**
    - 유저 플레이량 지니계수 0.78, 게임 소유량 지니계수 0.80으로 상위 10% 유저가 전체 플레이량의 59.3%를 차지하는 것으로 확인
        - 활동량이 소수에 극단적으로 쏠려 있어, 평균만으로는 유저를 설명하기 어렵다는 것을 시사
    - 같은 유저·같은 게임이 두 번 이상 들어간 중복 13,861쌍을 제거 규칙으로 정리(1,309,380 → 1,295,519행)
    - 평가를 많이 하는 유저일수록 플레이도 많이 할 것 같지만, 평가 참여율이 가장 높은 구간의 플레이 비율이 오히려 41.4%로 가장 낮게 확인
        - 평가와 플레이는 같은 방향으로 움직이지 않기 때문에, 평가 참여율을 퍼널 단계가 아니라 별도의 참여도 지표로 분리
    - 게임 변수 14개가 서로 어떻게 얽혀 있는지 전수 확인
        - 인기와 관련된 지표들(평가자 수·소유자 수·위시 수)은 서로 0.82~0.92로 거의 같이 움직이고, 평점과도 0.75~0.81로 강하게 연결
        - 반면 복잡도는 플레이 시간(0.66)·권장연령(0.54)과는 강하게 묶이지만, 평점과는 0.41~0.54로 그보다 약하게 연결
        - 인기 관련 지표들이 하나의 덩어리로 움직인다는 이 구조가, 이후 [02.Funnel](jupyter/02.Funnel_Retention.ipynb)에서 "인기도가 복잡도보다 강한 신호"로 나오는 배경이 된다

활동량이 소수에게 쏠려 있다는 걸 확인했으니, 이제 그 소수와 나머지가 어디서 갈리는지를 봐야 한다. 퍼널을 실측해보니 가장 크게 빠지는 구간은 게임을 사고 나서 처음 플레이하기까지였다(-32.5%p). 그래서 다음 단계에서는 이 구간을 통과하는 사람과 못 하는 사람이 무엇이 다른지 분석한다. 여기서 "손실"은 시간이 지나며 이탈한 게 아니라 한 시점에서 다음 조건으로 못 넘어간 상태를 뜻한다.

- **[02.Funnel](jupyter/02.Funnel_Retention.ipynb)**
    - 퍼널 통과와 관련된 후보 변수 네 개를 효과 크기로 비교한 결과, 보유 게임 수(0.43, 중간~큰 효과) > 평가 참여율(0.29, 작음~중간) ≈ 마지막 로그인 이후 지난 날짜(0.28, 작음~중간) > 가입 후 지난 햇수(0.25, 작음~중간) 순으로 확인
    - 네 변수를 한 모델에 같이 넣어 서로의 영향을 걷어내고 봐도 전부 유의하게 남음, 다만 네 변수를 다 합쳐도 설명력 자체는 크지 않음(약 12% 수준)
        - 보유 게임 수(log)의 오즈비 1.60으로 가장 크게 확인, 보유 게임이 늘수록 플레이 확률도 함께 상승
        - 평가 참여율의 오즈비는 0.52로 확인 → 다른 조건이 같을 때 평가만 열심히 하는 유저일수록 오히려 플레이 확률이 낮다는 것을 시사, [01.EDA](jupyter/01.EDA.ipynb)에서 본 패턴과 같은 방향
        - 다만 단일 변수만으로 "누가 전환하는가"를 설명하기는 어렵다는 것을 시사
    - 유저가 아니라 게임 쪽을 보면, 그 게임이 얼마나 유명한지(0.22)가 얼마나 복잡한지(0.13)보다 플레이 여부와 더 관련 있는 것으로 확인
        - 다만 둘 다 약한 수준이라, 인기 쪽이 상대적으로 조금 더 뚜렷하다는 정도로만 해석

보유 게임 수가 네 변수 중 가장 강한 신호였지만(효과 크기 0.43), 정작 가진 것 중 실제로 몇 %를 플레이했는지와는 **반대 방향**으로 움직였다(-0.13). 많이 가진 사람일수록 "한 번이라도 해봤다"는 조건은 쉽게 통과하지만, 가진 것 대비 실제로 손대는 비율은 오히려 떨어진다는 뜻이다. 결국 보유 게임 수 하나만으로는 "많이 갖고 실제로 잘 쓰는 사람"과 "많이 갖고 쟁여만 두는 사람"이 같은 그룹으로 묶여버린다. 그래서 다음 단계에서는 보유 게임 수와 활용도를 각각 다른 축으로 놓고, 손실이 가장 큰 이 구간에 실제로 누가 있는지 들여다본다.

- **[03.Segment](jupyter/03.Segment_Wishlist.ipynb)**
    - 보유 게임 수와 활용도를 각각 절반으로 나눠 교차시켜, 미플레이(956명)를 뺀 나머지를 몰입형·수집가형·집중형·저관여형 네 유형으로 분류
        - 두 변수 모두 "몇 개 이상이면 많다"는 정해진 기준이 없어, 유저를 절반씩 가르는 중앙값을 경계로 사용
        - 같은 두 변수로 군집화(K-means)를 따로 돌려 비교한 결과 일치도 0.64로 확인
        - 다만 군집이 얼마나 뚜렷하게 갈리는지를 재는 실루엣 계수는 0.32~0.35로 낮았고, 그룹 수를 2개부터 10개까지 바꿔봐도 값이 거의 그대로였음(0.33~0.38)
    - 보유 게임이 많을수록 "한 번이라도 해봤는지" 여부는 통과하기 쉽지만, 가진 것 중 실제로 플레이한 비율은 오히려 낮은 것으로 확인(-0.13)
    - 위시리스트를 쓰는 비율은 몰입형·수집가형이 79%대로 가장 높고, 미플레이가 46%로 가장 낮게 확인
    - 위시리스트에 담은 게임이 실제 소유·플레이로 이어진 비율은 다섯 유형 모두 1% 안팎으로 낮게 확인
        - 몰입형이 다른 유형의 2~4배로 상대적으로 높지만 절대 수준 자체가 낮음
        - 위시 우선순위별로 나눠 봐도 일관된 차이는 나타나지 않음

위시리스트는 "곧 살 것"의 예고가 아니라 관심 표시에 가깝다. 담아둔 게임의 99%가 실제 플레이로 이어지지 않기 때문이다.

그룹 수를 어떻게 바꿔도 군집이 뚜렷해지지 않았다는 건 이 데이터에 자연스럽게 갈라지는 경계가 애초에 없다는 뜻이다. 네 유형은 데이터가 찾아준 게 아니라, 두 축을 나눠 보기 위해 정한 틀이다. 이 틀이 쓸모 있는지는 "정의에 쓰지 않은 것에서도 차이가 나는가"로 판단해야 하는데, 지금까지는 전부 한 시점에 모은 데이터로만 확인한 상태다. 그래서 다음 단계에서는 실제 플레이 로그를 가져와, 이 구분이 시간이 지나도 유지되는지 확인한다.

- **[04.Trend](jupyter/04.Trend.ipynb)**
    - **반복 플레이한 유저는 안 한 유저보다 실제 활동 기간이 더 길 것이다(H1)**: EDA에서 "같은 게임을 두 번 이상 했다"는 것까지만 알 수 있었고 그게 언제였는지는 몰랐기 때문에, 이게 정말 오래가는 참여인지 확인이 필요했음
        - 실제 플레이 로그로 반복 플레이 여부에 따라 활동 기간이 다른지 비교
        - 결과: 반복 플레이 있는 647명은 활동 기간 중앙값 8년으로 지금도 활동 중, 없는 82명은 1년에 그치고 7년 전에 멈춘 것으로 확인(효과 크기 0.81로 매우 큼, 다만 없는 쪽이 82명으로 적어 해석에 주의) → **채택**
    - **보유 게임 수·활용도로 나눈 유형 간 활동 지속성 차이는 시간이 지나도 유지될 것이다(H2)**: 네 유형의 경계가 군집화로 어느 정도 뒷받침되긴 했지만 전부 한 시점 데이터라, 시간이 지나도 이 차이가 유지되는지는 알 수 없었기 때문에 확인이 필요했음
        - 유형별로 실제 플레이 로그의 마지막 활동 시점과 활동 지속 기간을 비교
        - 결과: 몰입형·수집가형·집중형은 지금도 활동 중, 저관여형만 4~5년 전에 멈춘 것으로 확인 → **부분 채택**
    - **최근에 가입한 유저일수록 실제로 게임을 플레이하는 비율이 더 낮을 것이다(H3)**: EDA에서 가입자 수 흐름에 정체·감소 구간이 있다는 건 확인했지만 "가입 자체가 준 것"인지 "가입은 했는데 실제로 게임을 안 한 것"인지는 구분하지 못했기 때문에, 신규 유입 정체라는 프로젝트 목표와 가장 직접 연결되는 이 질문을 확인해야 했음
        - 가입연도별로 실제 플레이 로그를 한 번이라도 남긴 비율을 비교
        - 결과: 2005년 이전 가입자 85.5%에서 2021년 이후 가입자 47.0%로 하락(가입연도 구간당 150~230명이라 방향만 읽음) → **채택(방향성)**

## 🧪 가설 검증

앞선 세 분석이 한 시점에 모은 데이터만으로는 답하지 못하고 남긴 질문 세 가지를, [04.Trend](jupyter/04.Trend.ipynb)에서 실제 플레이 로그로 검증했다. 대상은 플레이 로그를 수집한 1,065명 중 실제 기록이 있는 730명이다.

| 가설 | 검정 결과 | 판정 |
|---|---|:---:|
| H1. 반복 플레이한 유저는 안 한 유저보다 실제 활동 기간이 더 길 것이다 | 반복 플레이 있음 647명은 활동 연수 중앙값 8년·2026년까지 활동, 없음 82명은 1년·마지막 활동 7년 전(효과 크기 0.81, 매우 큼) | 채택 |
| H2. 보유 게임 수·활용도로 나눈 유형 간 활동 지속성 차이는 시간이 지나도 유지될 것이다 | 몰입형·수집가형·집중형은 지금도 활동 중, 저관여형만 마지막 활동 4~5년 전 | 부분 채택 |
| H3. 최근에 가입한 유저일수록 실제로 게임을 플레이하는 비율이 더 낮을 것이다 | 실제로 한 번이라도 플레이한 비율이 2005년 이전 가입자 85.5%에서 2021년 이후 가입자 47.0%로 하락 | 채택(방향성) |

각 가설을 왜 세웠고 어떻게 확인했는지는 위 `🔬 Analysis`의 04.Trend 항목에 정리했다.

H2에서 가장 중요한 건 결과가 예상과 반대로 나왔다는 점이다. 분석 전에는 "많이 갖고 있으면서 안 쓰는" 수집가형이 위험군일 거라 봤는데, 실제 활동 기록을 열어보니 수집가형은 지금도 꾸준히 활동 중이었고 정작 몇 년째 돌아오지 않은 쪽은 적게 갖고 그마저도 안 쓰던 저관여형이었다. 보유 게임 수 하나로만 유저를 나눴다면 이 둘을 구분하지 못해 엉뚱한 그룹에 재활성화 캠페인을 돌렸을 것이다.

## 🧭 핵심 인사이트 → 액션

- 유저를 가장 많이 잃는 순간은 게임을 산 뒤 처음 플레이하기까지다
    - 게다가 이 문턱은 고정돼 있지 않고, 최근에 가입한 사람일수록 넘는 비율이 더 낮아지고 있다(H3)
- 같은 게임을 두 번 이상 반복 플레이했다는 사실 하나가, 그 사람이 앞으로 몇 년을 더 활동할지와 강하게 연결돼 있다(H1)
    - 한 시점 데이터만 보고 내린 판단이 근거 없는 추측은 아니었다는 뜻이다
- 많이 가진 유저가 잘 쓰는 유저는 아니다
    - 비율 지표, 군집화, 실제 활동 기록이라는 서로 다른 세 방향에서 같은 결론이 나왔다(H2)
- 진짜 위험한 쪽은 많이 갖고 안 쓰는 사람이 아니라, 적게 갖고도 몇 년째 돌아오지 않는 사람이다(H2)
- 평가만 하고 플레이는 하지 않는 층이 실제로 존재하고, 위시리스트는 곧 살 것의 예고가 아니라 관심 표시에 가깝다

아래 액션은 위 인사이트에서 도출한 제안이다. 다만 데이터가 인과를 증명한 것이 아니라 관찰된 패턴에서 나온 가설이므로, 각 행에 실행 후 확인할 검증 방법을 함께 적었다.

| 타깃 | 근거 | 제안 액션 | 검증 방법(제안) |
|---|---|---|---|
| 최근 가입자(2021년 이후) | H3 | 가입 후 3일 안에 유저가 실제로 한 행동에 맞춰 자동으로 안내 메일 발송: 가입 즉시 "첫 게임 등록하는 법" 안내 → 24시간 지나도 안 하면 리마인드 → 3일째까지 기록이 없으면 입문용 게임 추천. 정해진 시간마다 일괄 발송하는 것보다 유저 행동에 반응해 보내는 메일의 전환율이 2~3배 높고, 가입 후 3일 안에 아무 활동이 없으면 이탈 확률이 90% 뛴다는 SaaS 업계 사례 참고 | 가입 후 3일 내 첫 플레이 기록률(코호트별 비교) |
| 게임을 산 직후의 모든 유저 | 퍼널 최대 손실 구간(-32.5%p) | 게임 등록 즉시 "첫 플레이를 기록하면 배지를 준다"는 작은 목표 제공, 7일째까지 기록이 없는 유저에게 "플레이 기록하는 법" 안내 메일 발송. 듀오링고가 배지·연속 학습일 같은 작은 성취 요소로 완료율을 30%가량 끌어올린 사례 참고 | A/B 테스트로 배지 노출군 vs 비노출군의 첫 플레이 전환율 비교 |
| 저관여형(몇 년째 안 돌아옴) | H2 | 메일 한 통이 아니라 3~5회에 걸쳐 순서대로 발송: 1차는 가볍게(마지막 활동일·보유 게임 언급) → 2차는 취향에 맞는 신작 소개 → 3차는 확실한 혜택(제휴 게임샵 할인쿠폰)으로 마무리, 복귀 시 "그동안 놓친 소식" 화면 제공. 이탈 고객 재유치는 메일 한 통보다 여러 번 나눠 보낼 때 전환율이 훨씬 높고, 할인폭보다 추천 상품이 취향에 맞는지가 전환에 더 크게 작용한다는 이커머스 업계 사례 참고 | 캠페인 발송 후 30~45일 내 재활동 비율, 단계별 오픈율 |
| 수집가형(쟁여둔 건 많지만 지금도 활동 중) | H2 | 보유 게임 중 안 해본 게임을 플레이 시간·평점이 비슷한 게임과 엮어 "다음에 해볼 게임"으로 추천(스팀이 보유 게임 중 안 한 것을 추천해주는 기능 참고), "이번 주 쟁여둔 게임 하나 꺼내보기" 주간 미션 운영(완료 시 배지 지급) | 추천 클릭률, 챌린지 참여 후 플레이 전환율 |
| 평가만 하고 플레이는 안 하는 유저 | [Segment 분석](jupyter/03.Segment_Wishlist.ipynb) | 평점을 남긴 직후 화면에 "플레이 기록도 남겨보세요"라는 안내를 가볍게 띄우고, 처음 플레이를 기록하면 소액 포인트 지급. 이미 평점까지 남길 만큼 관심이 있는 유저라, 경고성 문구보다는 작은 보상을 주는 쪽이 더 적합하다고 판단 | 안내 노출 후 7일 내 플레이 전환율 |
| 집중형(원하는 게임과 실제 하는 게임의 난이도 차가 가장 큼) | [Segment 분석](jupyter/03.Segment_Wishlist.ipynb) | 위시리스트에 담은 게임과 난이도가 비슷한 신작을 개인화 추천. 이커머스에서 실제 구매 이력 기반 추천이 일반 베스트셀러 추천보다 전환율이 2.1배 높았던 사례 참고 | 추천 후 구매·플레이 전환율 |

다만 이 프로젝트가 다룬 건 이미 가입해서 게임을 보유한 사람들의 행동뿐이다. 신규 유입 자체를 늘리는 액션은 이 데이터로 증명할 수 없으므로, 위 제안은 기존 유저를 붙잡는 데서 확인된 패턴을 신규 유저 온보딩 설계에 참고할 수 있는 가설로 남겨둔다.

## 📐 표본 설계와 재수집

- 원래 2024년 팀 프로젝트에서 물려받은 유저 명단(`user_list.csv`, 194,643명)에서 표본을 뽑았음
    - 가입연도 분포를 확인하다 2016~2021년에 표본이 몰려 있고 2025~2026년 가입자는 아예 0명이라는 걸 발견, 명단이 2024년 시점에 고정돼 있어 그 이후 가입자가 들어올 수 없는 구조였음
- 기존 명단과 무관하게, 게임에 평점을 남긴 유저를 API로 직접 수집해 새 명단을 구축(`frame.py`)
    - 새 명단에서 600명을 먼저 뽑아 기존 명단과 가입연도 분포를 비교, 편향이 실제로 존재함을 수치로 확인(`docs/sampling_design.md`)
- 기존 명단을 부분 보정하는 대신, 새 명단으로 3,000명을 처음부터 다시 수집(`main_frame.py`)
    - 3,000명이라는 숫자는 임의로 정한 게 아니라, 비율을 ±2%p 오차로 추정하는 데 필요한 표본 크기(2,400명)를 공식으로 계산한 뒤 수집 중 유실될 몫을 더해 잡은 값
- 편향 검증 이전의 구버전 분석은 보존하지 않고 폐기, 이 프로젝트의 분석은 새 표집틀로 재수집한 데이터만 사용

## 🗄️ Data Pipeline

```
data/*.csv (원본, BGG API 그대로)
   ↓ scripts/load_bigquery.py
bgg_raw     : 원본을 그대로 옮김. 전부 STRING.
   ↓ sql/staging/preprocessing.sql (SAFE_CAST, NULLIF, CASE WHEN)
bgg_staging : 타입 캐스팅 + 결측 마커 정규화. 분석 가능한 상태.
   ↓ sql/marts/*.sql (GROUP BY, 윈도우 함수)
bgg_mart    : 퍼널·코호트·세그먼트 등 분석 결과. 노트북이 조회하는 곳.
```

원본을 전부 문자열로 받는 이유는 `rank`처럼 숫자여야 할 컬럼에 `"Not Ranked"` 같은 문자열이 섞여 들어오기 때문이다. 타입을 자동으로 추론하게 맡기면 이런 값 하나 때문에 컬럼 전체가 엉뚱한 타입으로 잡히고, 그 사실을 눈치채기도 어렵다. 그래서 원본은 그대로 받아두고, 타입 변환은 SQL에서 명시적으로 처리한다.

**데이터 규모** (BigQuery `INFORMATION_SCHEMA` 실측 기준)

| 테이블 | 행 수 | 내용 |
|---|---:|---|
| `user_info` | 3,000 | 유저 기본정보(user API) |
| `user_item` | 1,309,380 | 유저×게임 보유 게임(collection API, own=1) |
| `user_wishlist` | 160,565 | 유저×게임 개인 위시리스트(wishlist=1) |
| `user_play` | 1,272,008 | 실제 플레이 로그(plays API) |
| `item_details` / `item_stats` | 각 85,442 | 게임 상세정보 · 통계(thing API) |
| `item_link` | 1,240,967 | 카테고리·메커닉·디자이너·퍼블리셔(long 포맷) |

컬럼 단위 스키마와 각 컬럼의 의미는 [`docs/data_model.md`](docs/data_model.md)에 정리했다.

```
├── jupyter/                        # 분석 4편(EDA → Funnel → Segment → Trend)
├── docs/                           # 데이터 모델, 품질 체크, 표본 설계, 데이터셋 비교
├── assets/                         # README용 차트·로고 이미지
└── data/                           # 수집·적재 산출물(재현 가능한 것만, git 제외)
```

- `scripts/`(무엇을 할지, 얇은 오케스트레이션)와 `src/collectors/`(어떻게 할지, 재사용 가능한 파싱/HTTP/체크포인트 로직) 분리
    - `src/collectors/`의 파싱 함수는 `test_parsers.py`가 API 호출 없이 직접 단위 테스트, `src/loaders/`도 이 모듈들을 그대로 import
    - 로직이 스크립트 안에 갇혀 있으면 두 재사용 모두 불가능

### 실행 순서 (7단계, 순서대로)

```bash
uv run python -m scripts.collect.frame          # 1. 신규 표집틀 구축
uv run python -m scripts.collect.verify_frame    # 2. 표집틀 검증(600명)
uv run python -m scripts.collect.main_frame      # 3. 본수집(3,000명)
uv run python -m scripts.collect.thing           # 4. 아이템 상세(배치 20개)
uv run python -m scripts.collect.wishlist        # 5. 위시리스트 보강 수집
uv run python -m scripts.collect_phase4_plays    # 6. 표본 플레이로그
uv run python -m scripts.load_bigquery           # 7. BigQuery raw 적재
```

각 단계는 체크포인트 기반이라 중단 후 재실행해도 이어서 진행된다. 국가/가입연도로 수집 대상을 제한하고 싶다면 저장소 루트의 `config.yaml`(`collect.countries`/`min_year`/`max_year`)을 채운다.

## 💡 Lesson and Learned

- 0으로 채워진 값을 결측으로 의심하지 않고 그대로 쓰면 통계가 조용히 왜곡되는 것으로 확인
    - `averageweight=0`을 걸러내지 않으면 "가벼운 게임" 비율이 21.5%p 차이 나고, 복잡도-평점 상관도 0.28로 과소평가됨
    - 값이 존재한다고 해서 전부 유효한 값은 아니라는 것을 시사
- 데이터가 수십만 행이면 아주 작은 차이도 p-value가 거의 항상 "유의미하다"는 판정을 내리기 쉬운 것으로 확인
    - 유의미하다는 것과 그 차이가 실제로 큰 차이라는 것은 다른 이야기라, 효과 크기 등으로 크기까지 따로 확인해야 한다는 것을 시사
- 표집틀 편향은 수집을 마친 뒤에야 알아채기 쉬움
    - 가입연도 분포를 초반에 확인해 시간 절단 편향을 스스로 발견
    - 부분 보정 대신 독립 검증표본으로 실측 확인 후 전면 재수집 → 이번 프로젝트에서 가장 큰 설계 교훈

## 🪞 회고

가장 아쉬운 건 유저가 사이트에 언제 들어와서 무엇을 봤는지에 대한 기록이 없었다는 점이다. BGG API가 주는 건 "언제 게임을 등록했고 언제 플레이했는지"까지라, 퍼널과 코호트를 결국 소유·플레이 여부로 근사할 수밖에 없었다. 접속 기록까지 있었다면 어느 시점에 이탈이 시작되는지를 훨씬 정확하게 짚을 수 있었을 것이다.

또 하나는 이 프로젝트가 다룬 대상 자체의 한계다. 이미 가입해서 게임을 보유한 사람들만 분석했기 때문에, 정작 "신규 유저가 왜 안 들어오는가"라는 원래 질문에는 직접 답하지 못했다. 그걸 보려면 아직 가입하지 않은 사람들의 데이터나 마케팅 유입 경로 데이터가 필요한데, 둘 다 이 프로젝트 범위 밖이었다.

분석 방법 측면에서는, 검정을 여러 번 반복하면서 다중비교 보정을 하지 않았다. 확증이 아니라 탐색 목적의 분석이라 보정이 오히려 적절하지 않다고 판단했지만, 개별 p-value를 엄밀한 근거로 쓰기보다 효과 크기와 방향성 위주로 읽어야 한다는 뜻이기도 하다.
